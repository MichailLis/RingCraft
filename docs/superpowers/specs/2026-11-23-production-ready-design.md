# Доведение RINGFORGE до продакшна — дизайн

Дата: 2026-11-23 · Статус: утверждён (структура и подход)

## Зачем

RINGFORGE — работающий в браузере параметрический конструктор проставок под автодинамики (React 19 + three.js, Vite).
Сделан в Google AI Studio. Функционально он готов: мастер из четырёх шагов, два слоя крепежа,
3D-вид, чертёж 1:1, экспорт DXF/STL/SVG/PNG. 35 тестов, проверка типов (в том числе `--strict`) и сборка проходят.

Цель — выложить его на Vercel как публичный сайт, за который не стыдно: репозиторий в порядке,
сбой интерфейса не превращается в белый экран, каждое изменение автоматически проверяется,
выкладка происходит сама.

## Цели

1. **Порядок в репозитории**
   - Одно название проекта — RingCraft — везде (см. «Решения владельца»).
   - Убрать хвосты AI Studio: `metadata.json`, `.env.example` с `GEMINI_API_KEY`/`APP_URL`, комментарии про
     `DISABLE_HMR` и плагин `copy-unbundled-src-assets` в `vite.config.ts` (папки `src/assets` нет).
     `public/assets/aistudio/*` — скриншоты-референсы, в коде не используются: убрать из `public/`.
   - README (что это, как запустить, как собрать, как деплоится), LICENSE, favicon, OG-картинка 1200×630.
   - Скрипты: `test`, `typecheck`, `lint`, `format`, `e2e`. Включить `strict` в `tsconfig.json`.
   - ESLint (flat config, typescript-eslint, react-hooks) + Prettier; исправить то, что найдут.
2. **Надёжность**
   - Error boundary вокруг приложения и отдельно вокруг 3D-вьюпорта: понятный экран,
     кнопки «Перезагрузить» и «Сбросить сохранённые данные». Отказ WebGL — сообщение и работающий чертёж 2D.
   - Версионирование данных в `localStorage` (`ringforge.state`, `ringforge.ui`, `ringforge.saved`):
     обёртка `{ v, data }`, миграция старого формата без версии, при ошибке — откат к значениям по умолчанию
     без падения. Покрыть тестами.
   - Вынести сборку бинарного STL из `App.tsx` в `src/core/` и покрыть тестом:
     заголовок, число треугольников совпадает с размером файла, нормали конечные, сетка замкнута.
   - STL строится в `core` без рендерера — экспорт работает и без WebGL.
   - **Баг SVG-экспорта** (найден при разборе): файл «SVG 1:1» сохраняется размером 1400×1400 px
     и с текущим масштабом/сдвигом экрана — при приближенном чертеже в файл попадает только видимая часть,
     а печать не 1:1. Исправить: весь чертёж, `width`/`height` в мм. Это намеренное изменение SVG.
   - Шрифты IBM Plex Sans/Mono — локально через `@fontsource`, убрать Google Fonts из `index.html`.
3. **Автопроверки (GitHub Actions)**
   - На каждый push и PR: установка через bun, typecheck, lint, unit-тесты, сборка.
   - Сквозной тест на Playwright (Chromium): открыть сайт, пройти мастер (типоразмер → дверь → динамик → экспорт),
     скачать DXF, STL, SVG и проверить, что файлы непустые и начинаются как положено; переключить 2D/3D.
4. **Выкладка на Vercel**
   - Подключение через Vercel Git Integration: `main` → продакшн, PR → preview-ссылка.
   - `vercel.json`: framework vite, `Cache-Control: public, max-age=31536000, immutable` для `/assets/*`,
     заголовки безопасности (`X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`,
     `X-Frame-Options: DENY`, CSP с `default-src 'self'` и разрешениями, которых требуют three.js и Vercel Analytics).
   - Vercel Web Analytics (`@vercel/analytics`), без cookie — баннер согласия не нужен.
   - Адрес на старте — `*.vercel.app`, свой домен — позже, вне этого проекта.

## Не цели

- Новые функции: овальные динамики, отмена действий, новые форматы экспорта.
- Рефакторинг больших файлов (`ControlPanel.tsx`, `App.tsx`) ради красоты — трогаем только то,
  что нужно для целей выше (например, вынос STL в `core`).
- Бэкенд, аккаунты, облачное хранение.
- Перевод интерфейса на другие языки.

## Анти-цели (провал, даже если «работает»)

- Меняется геометрия моделей или содержимое DXF/STL для тех же параметров — пользователи режут по этим файлам.
- Пропадают сохранённые у пользователей пресеты после обновления.
- Сайт тянет что-то со сторонних доменов, кроме аналитики Vercel.

## Ограничения

- Менеджер пакетов — bun (`bun.lock` уже в репозитории); тесты на `node:test`, запускаются `bun test`.
- Vercel-аккаунт и подключение репозитория делает владелец; код и конфигурацию готовит исполнитель.
- Пуш в GitHub — только с разрешения владельца.

## Подходы к деплою

| Подход | Плюсы | Минусы |
|---|---|---|
| **Vercel Git Integration** (выбран) | Ноль кода деплоя, preview на каждый PR, откат в один клик | Проверки CI и деплой идут параллельно |
| GitHub Actions + Vercel CLI | Деплой только после зелёного CI | Токены в секретах, больше конфигурации |
| Статический хостинг без Vercel | — | Владелец хочет Vercel |

Выбран первый: защиту «не выкатывать красное» даёт правило ветки `main` (PR + обязательные проверки),
а не сложный пайплайн.

## Что решено исполнителем (можно оспорить)

- Vercel Web Analytics вместо Google Analytics и подобных — без cookie и баннера.
- Шрифты локально через `@fontsource`.
- Playwright только Chromium — для одного браузера достаточно, остальные дорого держать в CI.
- Скриншоты `public/assets/aistudio/` удаляются (в git-истории остаются).
- CSP допускает `style-src 'unsafe-inline'` (React-атрибуты `style`) и `img-src data: blob:`
  (текстуры материалов рисуются на canvas, PNG-экспорт); точный набор подбирается по консоли браузера.
- Порядок работ: порядок в репо → надёжность → CI → Vercel; каждый блок — отдельный PR.

## Решения владельца

1. Название — **RingCraft** везде: `package.json`, `index.html` (title, description, OG), логотип в `HeaderBar`,
   штамп чертежа в `Viewport2D` (а значит и SVG-экспорт), README.
   Ключи `localStorage` (`ringforge.*`) **не переименовываются**, иначе пропадут сохранения пользователей;
   префикс — внутренняя деталь, переименование возможно только через миграцию со старых ключей.
2. Лицензия — **MIT**.
